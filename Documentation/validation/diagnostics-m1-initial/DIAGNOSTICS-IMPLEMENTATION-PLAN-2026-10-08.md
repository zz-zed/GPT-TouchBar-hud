# 内置诊断日志执行方案

2026-10-08。状态：执行计划，功能尚未实施。当前授权为制定方案；代码实施、试用、安装和发布分别记录结果。

目标是让用户在发生断连、任务状态异常、Touch Bar 或刘海显示异常后，通过应用导出一份可审阅的本地诊断包，支持还原故障前后的状态变化。默认不上传，不收集对话与账号用量，不改变现有任务判断、重连和显示逻辑。

| --- | --- | --- |
| M1 基础诊断 | 环境快照、关键事件、轮转存储、当前检查、预览导出、关闭与清除、无法打开应用时的取件说明 | 四条核心链路接入，隐私与异常测试通过，独立试用包可构建；实机缺口单独列出 |

M1 不接入自动上传、用户统计平台、第三方崩溃 SDK、整机 sysdiagnose 或全量系统日志。M2、M3 不作为 M1 本地交付的前置条件。后续实施默认先完成 M1。

## M1 产品行为

入口沿用“设置 → 通用 → 连接检查与诊断”，扩展为“诊断与反馈”。

1. 打开窗口先显示环境、记录状态、已有检查时间和可导出时间范围，不自动重连或刷新业务接口。
2. “检查当前状态”执行原有主动检查，结果注明检查起止时间，与历史事件分开呈现。
3. “导出诊断包”默认选择最近 30 分钟，可选择最近 2 小时或全部可用记录；实际覆盖不足时明确提示。
4. 问题描述和发生时间可选填，不阻塞导出。自由文本仅进入本次导出预览，不进入常驻事件日志；提示用户不要填写凭据或对话内容。
5. 生成不可变的导出快照，展示摘要、文件清单、采集范围、大小、缺失项，并支持查看每个文本文件。用户保存的内容必须与预览快照一致；再次采集需重新预览。
6. 使用保存面板导出 ZIP，不自动发送、打开上传页或复制到剪贴板。取消、失败和部分成功各有明确反馈。

基础记录默认开启，设置中明确说明“仅保存在本机”。首次升级后以设置说明和隐私文档告知用途、保存范围和关闭方法，不弹出阻断使用的窗口。

“关闭记录”停止新增持久化事件及系统日志镜像，不删除既有文件；主动检查与显式导出仍可使用。“清除记录”只清除本应用拥有的诊断文件和临时快照，并使打开的旧预览失效，不修改业务缓存、账号数据、Hooks 或更新恢复材料。用户另存的 ZIP 和操作系统已接收的日志不属于可清除范围，界面需说明。

## 事件与环境字段

公共字段采用版本化结构：`schemaVersion`、UTC 时间、进程会话随机 ID、会话内序号、单调时钟耗时、模块、事件名、严重程度、固定结果码，以及该事件允许的类型化字段。时间线以会话和序号辅助排序；系统时间调整不能产生负耗时或伪造跨重启的连续时长。

| 模块 | M1 必须覆盖的证据 | 边界 |
| --- | --- | --- |
| 环境 | App 版本与 Build、可用的构建来源标记、macOS 版本与 Build、机型、硬件与进程架构、Rosetta 状态、宿主版本、运行位置类别 | 缺失值为未知；位置只用 Applications、Downloads、DMG、Other 等固定类别 |
| 生命周期 | 启动、准备退出、休眠、唤醒、会话暂停与恢复、上次关闭标记状态 | 未发现关闭标记只能称为“未确认正常结束”，不能判定崩溃 |
| 连接 | 运行时发现、启动结果、连接代次、初始化、请求类型与耗时、超时、退出状态、重试与恢复 | 业务连接和诊断连接使用不同来源标记，不导出 RPC 请求 ID 或原始错误 |
| 显示 | 用户选择、硬件判断、私有接口兼容性、模式与屏幕布局变化、显示或隐藏请求、抑制原因、可观察遮挡状态 | 不记录屏幕内容、其他应用名称、显示器序列号；不周期性截屏 |
| 任务 | 任务开关和模式、数据目录来源类别、索引读取结果、候选数量、读取失败或截断、生命周期转换、聚合结果及界面接收结果 | 区分生产状态、保存偏好与独立检查；无证据不写为无任务，不改变普通界面的中性呈现 |

任务链路使用进程内的扫描批次号，关联“读取与判断 → 聚合 → 主线程接收或丢弃 → 提交显示状态”。任务和轮次若确需关联，使用进程内随机映射代号，原始 ID 只在内存中使用，映射在重启后重建。跨重启以版本、时间和环境对照，不创建长期设备或账号标识。

事件接口使用枚举和明确字段，不开放任意字典或自由字符串的通用写入入口。基础模式只写关键变化、失败与恢复；稳定的正常轮询不逐条落盘。同类错误按固定窗口聚合，保存首次、末次时间和次数。

所有落盘与系统日志输出共享白名单。禁止邮箱、账号标识、额度和 Token 数值、对话、任务标题、工具参数、完整路径、凭据、配置正文和原始响应。仅通过原始错误类型及已知错误码映射固定分类，不直接写 `localizedDescription`。对现有 `NSLog` 调用做同范围检查，避免旁路泄露。

## 存储与资源约束

以下为实施默认值及验收目标，尚非性能实测结论。若实测需要调整，应在验证记录中说明依据。

| 项目 | M1 约束 |
| --- | --- |
| 本地位置 | `~/Library/Application Support/GPT TouchBar HUD/Diagnostics/`，与业务缓存分目录 |
| 文件权限 | 目录 `0700`，事件和临时文件 `0600`；拒绝符号链接跳出自有目录 |
| 保存期限 | 最长 72 小时，基础事件总量最多 10 MiB；先达到的限制生效 |
| 轮转 | JSONL，单文件最多 1 MiB，轮转前检查字节预算；只清理自有已识别文件 |
| 输入与队列 | 单事件编码最多 4 KiB；队列同时限制 512 条和 1 MiB，达到任一上限开始丢弃并累计缺口 |
| 写盘 | 专用串行后台队列；正常事件最多等待 5 秒或累计 32 KiB 后批量写入，错误和退出触发异步刷新 |
| 临时空间 | 同时最多一次导出；快照与 ZIP 合计预留上限 25 MiB，超限停止并保留可读错误提示 |
| 导出时间 | 后台采集与打包设置 30 秒截止时间，支持取消；预览等待用户操作不计入截止时间 |
| UI 线程 | 不执行文件扫描、编码、压缩、同步子进程或等待落盘；AppKit 状态只做轻量值快照 |

生产记录不新增独立的高频定时器，不启动外部命令查询日常环境。写入失败后退避，不反复写日志来报告写日志失败；恢复后输出一次缺口摘要。队列满、磁盘满、权限拒绝和损坏尾行都不能改变业务状态或阻止主功能运行。

退出不等待无限刷盘，不增加独立的叠加退出等待；在现有退出协调流程内尽力保存，允许最近一小段记录丢失。关闭和清除操作递增记录代次，拒绝旧队列晚到写入，防止刚清除的内容重新出现。

本地文件是导出的主要来源。Apple 系统日志仅作为固定错误与关键状态的辅助输出，不以 `OSLogStore` 或全量 `log collect` 作为 M1 的必要依赖；系统侧保留周期由操作系统管理。保持 macOS 11 部署目标，逐项核验新 API 的可用性。

## 诊断包与无法启动时的获取

| 文件 | 内容 |
| --- | --- |
| `summary.txt` | 问题描述、环境概要、检查结果、关键事件与明确缺口，不自动下根因结论 |
| `environment.json` | 白名单环境字段、每项的取得状态和快照时间 |
| `events.jsonl` | 所选时间范围内的结构化事件；不包含新的主动检查结果以外的原始业务数据 |
| `checks.json` | 可用的主动检查结果和时间；没有执行时明确标记未执行 |
| `manifest.json` | 格式版本、导出 ID、请求与实际时间范围、文件清单、大小与 SHA-256、丢弃数量及部分失败状态 |

清单只列其他文件的哈希，避免自引用。包内文件名使用固定名称，归档只读取冻结快照中的允许文件；不递归打包应用支持目录，不带入符号链接、更新日志或原始会话日志。输出文件名使用产品名、时间和短随机编号，不包含用户或设备名称。

单项采集失败时继续导出其余内容，标明失败原因和可用范围。最终 ZIP 写入成功并完成基础可读性校验后才显示保存成功；取消或失败时清理本次临时材料，应用下次启动时只清理可确认属于自身的过期临时材料。

M1 文档提供 Finder 前往诊断目录的取件步骤。应用无法启动或卡死时，可手动复制已有事件文件并发送；这属于应急原始诊断记录，不宣称具备完整预览包和当前检查结果。默认未记录账号、对话或真实路径的约束在此情况下仍必须成立。

系统崩溃报告进入 M3：优先引导用户获取本应用对应报告，先审阅再附加，不默认复制整个 DiagnosticReports 目录。发布侧需保存与每个架构及二进制 UUID 匹配的符号材料，才能支持后续符号化。

最小实机流程是：正常运行导出一次 → 保留故障现场导出 → 只重启 HUD 后再导出 → 如仍异常，再重启宿主后导出。休眠唤醒和外接屏另做单独场景，不把“重启后恢复”直接当作根因证明。任何重启均由测试操作者主动执行。

## M2 与 M3 后续任务

M2 的详细模式在内存保存启用状态，重启默认关闭；15 分钟截止时间计入休眠，唤醒后先核对截止时间再继续记录。详细事件最长保留 24 小时、最多 20 MiB，与基础记录合计最多 30 MiB，导出临时预算相应调整。可手动停止和添加固定复现标记，更多细节不放宽隐私白名单。

详细模式可增加每次请求的安全元数据、扫描阶段耗时、固定原因的候选排除计数和低频进程资源样本。只使用生产已读取的数据；额外索引检查必须单独按需触发并标记为诊断观察。M1 不导出完整 stderr；后续如需错误特征，仅允许有界解析已知模式并输出固定分类，原文仍不持久化。

M3 按实际收到的诊断包决定优先级，分别补齐预告、通知、启动项和更新阶段证据，以及崩溃报告与符号留存。旧安装日志可能含路径等自由文本，不直接并入诊断包。自动上传若以后提出，需要另行确定接收方、保留和删除规则及用户发送动作。
