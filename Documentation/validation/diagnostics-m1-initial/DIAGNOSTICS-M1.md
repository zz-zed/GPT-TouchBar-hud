# 本机诊断与反馈（M1）

本轮增加可审阅的本地诊断包。它帮助对照连接、休眠与恢复、任务状态和显示请求的时间线，不会自动判断根因，也不会自动上传。

## 使用

在“设置 → 通用 → 诊断与反馈”打开诊断窗口。打开窗口只读取环境、已有检查和本地记录；“检查当前状态”才建立独立的短时诊断连接，不会重启 HUD 或宿主。检查结果与生产连接事件分别标记。

选择最近 30 分钟、最近 2 小时或全部可用记录，按需填写问题描述和发生时间，然后生成预览。描述不要包含账号、凭据或对话内容；这部分只进入本次可审阅的快照，不进入常驻事件文件。预览冻结后，继续产生的新事件不会混入保存内容。修改范围或描述后需重新生成预览。

可逐一查看以下五个文件，再通过保存面板保存 ZIP：

| 文件 | 内容 |
| --- | --- |
| `summary.txt` | 环境与检查摘要、问题描述、时间范围、缺口和部分失败 |
| `environment.json` | 受限环境字段及每项 known / unknown 状态 |
| `events.jsonl` | 范围内的类型化事件，按进程随机会话号和序号辅助排序 |
| `checks.json` | 已有主动检查与起止时间；未执行时明确标记 |
| `manifest.json` | 包版本、范围、缺口、其他四个文件的大小与 SHA-256 |

保存成功仅表示 ZIP 已写入并经过基础可读性检查，不代表任何实体设备验证通过。为保证异常退出后的临时文件可在自有目录清理，ZIP 先在诊断目录暂存，再原子移动到保存位置；跨磁盘保存会提示先保存到用户资料所在磁盘，再用 Finder 移动。

## 保存范围与控制

基础记录默认开启，仅保存在 `~/Library/Application Support/GPT TouchBar HUD/Diagnostics/`。事件最多保留 72 小时，合计最多 10 MiB，单文件最多 1 MiB；事件队列最多 512 条且不超过 1 MiB，单事件不超过 4 KiB。文件读写和导出在后台进行，队列满或写盘失败会形成可报告的缺口。清单分别计量确切丢弃事件、写入结果未确认的事件和缺口发生次数；无法读取记录时计数为未知，不填为零。应用运行时按最老记录的到期时间安排一次性清理；应用未运行时，在下次启动清理过期记录。

“关闭记录”停止新事件和系统日志镜像，保留尚未到期的已有文件；显式检查和导出仍可使用。“清除记录”使旧预览失效，只清除本应用识别的诊断材料。它不删除业务缓存、Hooks、更新恢复材料、用户另存的 ZIP 或操作系统已经收到的日志。重新开启后从新的记录代次开始。

导出同一时刻只进行一次，采集与打包设有 30 秒截止时间，快照与 ZIP 的合计预算为 25 MiB。取消、保存失败和部分采集失败分别显示；部分失败不会被解释为“没有事件”或“没有任务”。

## 证据边界

- Touch Bar 的事件只能证明能力判断、接口调用或请求被跳过，无法证明物理屏幕已经显示。
- 刘海的 visible 表示 AppKit 可观察窗口状态，不等于用户目视确认。
- 任务计数来自生产判断流程；读取失败和无证据保留未知，成功空结果才可为零。诊断不会改变任务激活条件或终态判断。
- 进程随机会话号、连接代次、扫描批次号只用于本次进程内对照；不创建长期设备或账号追踪标识。
- 上次正常关闭的记录只表示曾进入尽力保存的退出流程。缺少标记称为“未确认正常结束”，不能判定崩溃。
- 本次未扩展 M2 限时详细采集或 M3 崩溃报告收集。

## 应用无法启动时

1. 在 Finder 中按 **Shift–Command–G**（前往文件夹）。
2. 输入 `~/Library/Application Support/GPT TouchBar HUD/Diagnostics/`。
3. 将已有诊断事件文件复制到自己选择的位置，审阅后按需发送给排查人员。

这属于应急原始记录，不是完整的冻结预览包，也不包含新的当前检查结果。没有目录或事件文件，可能是未运行过此版本、关闭了记录、已清除或写入失败，不能当作故障未发生。不要复制整个 Application Support、Codex 会话目录、账号文件或系统 DiagnosticReports 目录。

## 字段白名单

公共字段：schemaVersion、UTC 时间、进程随机 sessionID、会话 sequence、单调时钟毫秒、固定 module / severity 和类型化 event。时间调整不改变单调耗时；不同进程的耗时不可连续相减。

| 类型 | 允许的值 |
| --- | --- |
| 环境 | 受限数字版本、Build、构建源摘要、系统版本和 Build、受限机型、硬件与进程架构、Rosetta 状态、固定宿主类别、运行位置类别；每项单独标记取得状态 |
| 生命周期 | 固定启动、退出请求、休眠、唤醒、锁屏及会话暂停/恢复阶段 |
| 连接 | business / check 来源、transport / store 层、固定阶段和请求类型、各层独立连接代次、结果码、毫秒耗时、重试次数及等待、退出状态 |
| 任务 | 固定阶段、扫描批次、模式、结果码、可选运行/未知/候选/失败/截断计数 |
| 显示 | Touch Bar / notch、固定动作/模式/原因/结果、可选窗口可见状态 |
| 存储缺口 | 固定原因、数量、首次及末次时间 |
| 组件失败 | 固定组件和失败分类，不包含错误正文 |

事件 API 不接受任意字典或自由字符串。禁止邮箱、账号、凭据、实际额度和 Token 数值、任务/轮次原始 ID、正文、标题、工具参数、原始响应或 stderr、完整路径和设备序列号。已有自由文本系统日志也改为同一类型化入口；关闭记录后停止这些辅助输出。

M1 的字段、存储、核心链路、预览导出及文档已实现。字段 / 存储 / 导出专项共 **305 项检查通过**（22 + 216 + 67），连同生产链路和现有回归，共 **19 个测试入口通过**。独立审查发现的半行恢复、FIFO 阻塞和关闭后重新启动的到期维护问题均已修复并复验；完整日志及原生窗口截图随验证记录保存。空闲行为回归通过不代表真实 CPU 或内存对照已完成。

试用 App 为 **0.1.40 / Build 43，arm64**。App 和 helper 的严格 ad-hoc 签名检查通过，Mach-O 与 Info.plist 最低系统标记均为 **macOS 11.0**；构建前后源码摘要与 App 内嵌摘要一致。

真实 Intel / Apple Silicon Touch Bar、刘海与无 Touch Bar 场景、macOS 11、故障系统、多屏、休眠唤醒，以及三轮 10 分钟开启/关闭 CPU 与内存对照均未完成。未启动、安装或替换任何正式或试用 App；未提交、合并、推送、打 tag 或发布。
