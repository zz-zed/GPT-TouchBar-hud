# 逐任务诊断追加审查记录

范围为 DIAGNOSTICS-TASK-TRACE-PLAN-2026-10-08.md 的 T1–T5，生产读取与计数规则不在修复范围。审查分为协议与生产采集实现、独立集成复审，以及最终同源回归。自动化结果与产物身份以 diagnostics-task-trace.json 为准。

## 已修正的问题

1. 主线程投递缓冲丢失后可能把旧快照挂到新 Hooks 业务状态。缺失引用现在会清空协调层、主线程旁路及下一次真实刷新引用；业务回调照常。消费者取实际输入任务数，错配明确记录 snapshotMismatch。新增真实 Hooks 建立基线后注入缺失 sequence 的回归，不把这项注入冒充真实缓冲耗尽。
2. clear 与 off/on 期间的旧观察可能进入新别名域。采集开始时捕获 session/generation，经生产 worker epoch、观察上下文、匿名映射和 Recorder admission 逐层校验；UI 也校验引用 session/generation。
3. 导出仅核对任务代号可能漏掉轮次或文件代号缺失。现在按同任务所有者分别核对任务、轮次和文件代号，缺少其中任一项不宣称完整。
4. 前序只有成员页完整，其他证据不完整时仍可能被用于差分。现在沿实际 previousSnapshotID 检查完整链；未核实的前序不产生完整成员差分。
5. 单快照消费观察数量可能使摘要膨胀。摘要索引和每快照消费均有固定上限，省略数明确保留；原冻结 events.jsonl 不因摘要截短而改写。
6. Hooks 重复文件头校验可能把静态轮询写成大量普通读取。无增量、偏移与 pending 不变时跳过该普通观察；真实增量和异常仍记录。
7. Hooks excludedSource 的闭集映射遗漏、具体成员移除原因被泛化。已补来源过滤、容量/来源移除、读取失败及过期的固定映射；仅淘汰单条证据不会退役整个任务。
8. 协调层将所有零运行快照写成 neutral，可能掩盖未知或完成反馈。缺少生产呈现事实时保留 unknown，Hooks 源快照直接复用既有 display adapter 的生产呈现，实际显示端按所消费的呈现记录。
9. 刘海普通模式显示完整数字，不能套用 Touch Bar 的 9+。各端现在从自己的实际呈现规则记录。

10. 选定范围只剩丢弃观察、没有任何快照时，原摘要和顶层清单可能没有强调缺口。现在按实际 taskTrace 事件数量判定，缺口本身也会使摘要与 manifest 声明覆盖不完整，并有冻结 ZIP 回归。

## 生产行为对照

普通模式独立复审确认：日期判定、首次基线、reset、256 KiB 跳尾、pending 清理、seek/read/offset 更新、生命周期策略、SQL 查询全文、50 ms busy timeout、路径过滤及 LIMIT 32 保持原行为。调度默认仍为 2 秒读取、10 秒发现；总数或业务值未变时不因诊断引用变化强制调用原 UI 更新。Hooks 保留原业务发布条件，逐任务观察通过独立回调，不新增任务激活证据。

大增量后仍在运行的夹具被少计，以及候选范围受限，都是保留的生产缺陷或覆盖限制。诊断测试通过不表示计数正确。真实宿主状态、实体设备可见性、最低系统与性能验证继续单列。

## 验证说明

普通模式与 Hooks 的端到端测试使用隔离 SQLite、真实 rollout 追加、生产 worker/调度、聚合、main callback、实际四端消费者和冻结 ZIP。夹具真值独立声明，字节长度包含换行；断言从系统 unzip 解出的 events.jsonl 与 manifest.json 读取。显示隐藏与开关、完成反馈 timer、缺页/缺前序/缺身份、clear/off/on、只读输出隐私均有对应检查。

完整回归首次遇到原 DiagnosticExportTests 的 pending 状态断言竞态：NSButton.performClick 会驱动 AppKit 事件循环，快速持久确认可能在返回前已完成。只调整测试为同步派发同一 action，确认 pending 前不让 main completion 运行；生产设置逻辑未改。首次失败日志保留在本轮证据目录。
