# 更新与恢复

[返回 README](../README.md) · [使用指南](USER-GUIDE.md) · [数据与隐私](DATA-AND-PRIVACY.md) · [卸载与清理](UNINSTALL.md)

## 日常更新

菜单栏显示当前版本与构建号，并提供“检查更新…”。“设置 → 更新”可关闭或重新开启自动检查、查看最近成功状态和可用新版本。

**自动检查只提示，不自动下载安装。** v0.1.35 在后台发现新版本时，只在菜单和设置中显示入口；v0.1.36 增加更醒目的提醒，见下节。无更新或检查失败时不弹窗。

主动查看版本说明后，可选择“安装并重启”“稍后”或“跳过此版本”。只有点击“安装并重启”才下载、校验和安装；安装完成后重启本工具，不退出 ChatGPT。手动检查始终可用，也能重新找到被跳过的版本。

### v0.1.36：更新提醒

- 菜单栏显示独立蓝色 `↑`，保留原任务图标和额度内容；菜单顶部提供带版本号的“查看更新”入口，支持原生键盘导航。
- “设置 → 更新 → 发现新版本时通知我”默认开启。系统已允许通知时，后台首次发现一个新版本会发出一次无声通知；点击查看版本说明。后台不会主动弹出授权窗口，尚未授权时可在设置中点击“允许系统通知”。
- 同一版本跨重启去重。启动时已有的版本、手动查看过的版本，以及关闭提醒或无权限期间发现的版本，不会集中补发通知；更新标记仍可使用。专注模式也可能阻止系统通知显示。
- “稍后”保留更新入口，不安排定时催促；“跳过此版本”清除此版本的标记与通知。升级完成后清除旧版本提示，发现更高版本后重新提醒。
- 通知开关独立于自动检查。关闭通知仍可自动检查；不会自动展开刘海、下载、安装或重启。

实现和故障验证记录见[更新提醒与 API 故障验证](UPDATE-REMINDERS-2026-09-28.md)。

### 下载与安装进度

选择“安装并重启”后，会打开独立的软件更新窗口。下载显示已接收字节、安装包大小、百分比和实测速率；百分比只表示安装包下载，100% 后仍需校验、安装与启动。

下载结束后，窗口依次显示完整性校验、签名与兼容性检查、准备新版、保留旧版、替换应用、等待新版启动等实际步骤。这些阶段使用活动指示，不显示估算的安装百分比或剩余时间。

下载期间可“取消下载”；网络下载失败时可“重新下载”，新尝试从 0 开始。进入校验与安装后不提供取消按钮。点击“后台继续”、关闭窗口或按 Escape 都只是收起窗口，更新继续进行；菜单栏及“设置 → 更新”的进度入口可重新打开同一窗口，不会重复安装。取消或失败后也可以重新检查版本。

替换应用时旧进程会退出，临时进度助手继续显示状态，并在旧菜单消失后提供临时菜单入口。新版在完成本工具的核心初始化后写入本次更新的启动确认，窗口才显示“更新完成”，约 3 秒后关闭助手。该确认不代表额度接口、任务监测或所有功能已经通过健康检查。

未在等待期限内收到确认时显示“尚未确认新版启动”，可以打开应用或查看恢复说明。超时不会自动替换可能正在运行的新版，晚到的有效确认仍能更新结果。实现与隔离验证见[更新进度验证记录](UPDATE-PROGRESS-2026-10-03.md)。

## 支持的安装位置

自动检查仅在应用标识正确，且位于下列正式安装路径时运行：

```text
/Applications/GPT TouchBar HUD.app
~/Applications/GPT TouchBar HUD.app
```

原地更新还要求该位置可写，不会请求管理员权限。开发 worktree、DMG 和其他目录不会被覆盖，可打开[最新 Release](https://github.com/zz-zed/GPT-TouchBar-hud/releases/latest)手动安装。

这里是本工具自己的安装路径规则。ChatGPT / Codex 宿主仍须满足[本机程序发现条件](DATA-AND-PRIVACY.md#额度与账号用量)，不要把两者混淆。

## 自动检查规则

启动后至少等待约 30 秒，到期才检查；成功后 24 小时内不重复请求。睡眠唤醒只补一次到期检查，开发 worktree、DMG、SwiftPM / `swiftc` 测试和刘海模拟入口不启动自动更新联网。

优先请求本仓库的 GitHub Release API；读取失败或 API 限流时回退到最新 Release 页面。同一次应用运行中，已知的 API 限流期限内不会重复请求 API；如果页面也无法读取，按 `Retry-After` 或限流重置时间退避。只接受本仓库最新正式版，不安装草稿、预发布版或降级版本。

API 单独不可用时，Release 页面可提供版本标签，再按本仓库固定附件名称选择对应架构的 DMG 和校验文件。附件通过 GitHub 下载直链访问，后续安装不再依赖 Release API。页面回退不提供版本说明正文，查看更新时会显示完整 Release 链接。

页面和 API 同时不可用时，无法发现新版本；附件不可用时，无法完成安装。已有可用版本入口在检查失败后保留，失败下载不会替换旧应用。v0.1.36 补充了 API 无效版本回退、HTTP 日期格式的 `Retry-After`、503 退避及严格来源检查。

失败按有限退避重试。最近尝试、最近成功、可用版本、跳过版本和重试期限会跨重启保存。手动检查与后台并发时共享一次请求；下载或安装期间不重复检查。

## 下载与完整性检查

按当前程序架构选择安装包，并核对 SHA-256、包大小、应用标识、版本、最低 macOS 要求及代码签名完整性。缺少对应安装包或 `SHA256SUMS.txt` 时拒绝安装。

**这些检查不等于 Apple 公证或独立发布者认证。** 当前使用 ad-hoc 签名，SHA-256 与安装包来自同一 GitHub Release；校验可发现损坏，但不能替代独立签名的更新源。更新信任本仓库及 GitHub HTTPS 分发。

若系统提示恶意软件或应用损坏，请停止操作，不要为完成更新而关闭系统安全保护。先重新下载，或向维护者反馈。

## 安装失败与旧版恢复

安装前保留旧应用。文件替换失败或启动请求被系统拒绝时尝试恢复；只有收到旧版的有效启动确认，才显示“旧版已恢复并完成启动”。未收到确认、恢复移动失败或安装进程中断时，窗口会提示进一步处理。成功发出启动请求不代表应用已完成启动。

尚不支持本次启动确认协议的旧版，在恢复后无法发送回执；窗口会显示“旧版已放回安装位置，但尚未确认启动”，请打开应用并核对状态。

暂存、日志和备份保留在安装目录同级的隐藏目录中，例如：

```text
.GPTTouchBarHUD-update-<随机标识>/
├─ RECOVERY.txt
├─ context.json / progress.json / install.json / launch.json
├─ progress-helper / progress-helper.log
├─ install-update.sh / install.log
└─ previous.app
```

具体文件取决于安装进行到哪一步。目录仅当前用户可访问，进度以本次会话的原子 JSON 文件传递；安装进行时短暂运行的助手不注册常驻服务。备份不会自动删除。

需要排查时，先保留对应目录，确认 `install.log` 与备份属于本次更新。`previous.app` 可用于手动恢复；恢复前退出本工具，并保留当前异常版本及日志以便排查。不要在安装仍进行时移动应用或清理暂存目录。

确认新版本正常运行、也不再需要回滚后，可在 Finder 中逐一审阅并移除对应备份。详细清理边界见[卸载说明](UNINSTALL.md#可选清理偏好缓存与更新备份)。

## 升级不会强制重置展示偏好

显示形式、面板隐藏状态和刘海常驻形态分别保存。新版本的默认值只影响没有保存过相关偏好的用户，不会为了展示新功能而强制打开面板。

从 v0.1.29 升级到 v0.1.30 时，原“刘海始终显示额度”关闭对应 Compact、开启对应 Peek；未保存过该偏好时才默认 Peek。外观与 Touch Bar 常驻选择继续保留，旧项目的迁移和自动启动兼容机制也继续适用。

## 联网信息与验证边界

检查更新会访问本仓库公开 GitHub Release，User-Agent 包含应用版本，不携带账号信息或任务内容。只有用户确认安装后才下载附件。详见[数据与隐私](DATA-AND-PRIVACY.md)。

[v0.1.30 发布记录](RELEASE-0.1.30.md)已验证双架构安装包与相关自动化检查，但**正式安装路径中的自动更新完整链路仍需真机验收**。不要把下载校验、签名完整性或自动化测试通过解释为所有实际升级场景都已验证。
