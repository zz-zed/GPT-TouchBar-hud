# 更新、校验与恢复

[返回项目说明](../README.md)

本文说明 GPT TouchBar HUD **v0.1.30 / Build 33** 的自动检查、安装校验和失败恢复边界。当前正式版发布页为 [v0.1.30](https://github.com/zz-zed/GPT-TouchBar-hud/releases/tag/v0.1.30)，发布证据见[发布验证记录](RELEASE-0.1.30.md)。

## 自动检查何时运行

自动检查开关默认开启；后台检查仅在以下条件同时满足时执行：

- App 正好安装在 `/Applications/GPT TouchBar HUD.app` 或 `~/Applications/GPT TouchBar HUD.app`。
- 应用标识与正式包一致。

开发 worktree、已挂载的 DMG、SwiftPM 或 `swiftc` 测试、刘海预览程序不会自动联网。用户可以在“设置 → 更新”关闭或重新开启自动检查，也可以随时从菜单手动检查。

启动后至少等待约 30 秒，到期才发起后台检查。一次成功检查后 24 小时内不会重复请求；睡眠唤醒只会补一次已经到期的检查。多处同时触发时，手动和后台检查共用同一个请求。

## 版本发现规则

应用优先读取本项目的 GitHub Release API。普通读取失败时，可回退到 GitHub 最新 Release 页面；遇到 `403`、`429` 等限流响应时，按 `Retry-After` 或限流重置时间等待。

候选版本必须是本仓库最新的公开正式 Release。以下候选会被拒绝：

- 草稿或预发布版本。
- 低于当前版本的降级版本。
- 缺少当前处理器架构安装包的版本。
- 缺少 `SHA256SUMS.txt` 或必要发布元数据的版本。

后台没有更新或检查失败时不会弹窗。发现新版本后，只在菜单栏和设置中显示入口，不抢占焦点、不自动展开刘海，也不会提前下载。失败后依次等待约 5 分钟、30 分钟和 2 小时，此后每天重试；最近尝试、最近成功、可用版本、跳过版本、连续失败次数和下次可重试时间会保存，以便重启后继续执行一致的计划。这套更新计划与额度的 60 秒刷新周期相互独立。

## 用户选择

打开新版本说明后，可以选择：

- **安装并重启**：下载、校验、替换应用并重新启动额度工具，不退出 ChatGPT / Codex。
- **稍后**：关闭当前提示，保留后续入口。
- **跳过此版本**：后台不再提示该版本；手动检查仍能重新找到它。

只有选择“安装并重启”后才会下载文件。下载或安装期间不会重复开始另一轮检查。

## 下载与安装校验

应用按当前运行架构选择 `arm64` 或 `x86_64` 安装包，并在替换前检查：

1. 下载文件大小。
2. `SHA256SUMS.txt` 中的 SHA-256。
3. 安装包与 App 可执行文件的目标处理器架构。
4. App bundle 标识。
5. 版本号和最低 macOS 要求。
6. 代码签名结构完整性。

任一校验缺失或失败，安装都会停止，当前应用保持不变。

原地更新仅支持可写的正式安装路径：

```text
/Applications/GPT TouchBar HUD.app
~/Applications/GPT TouchBar HUD.app
```

从开发目录、DMG 或其他路径运行时，应用不会覆盖当前文件，也不会请求管理员权限；它会改为打开 Release 页面，由用户手动安装。

## 失败与恢复

用户确认安装后，更新器会在应用同级创建隐藏目录：

```text
.GPTTouchBarHUD-update-<随机标识>/
```

该目录可能包含：

- `previous.app`：替换前的旧应用。
- `install.log`：安装步骤和失败信息。
- 下载、解包或恢复所需的临时材料。

文件替换失败或系统拒绝发起新版启动时，更新器会尝试恢复旧应用。一次成功的启动请求只说明系统接受了启动动作，不等于新版已经完成运行健康检查。因此更新目录及备份不会自动删除，便于失败后检查和手动恢复。

如果更新后应用无法正常启动：

1. 不要先删除 `.GPTTouchBarHUD-update-*` 目录。
2. 查看其中的 `install.log`，确认失败发生在下载、校验、替换还是启动阶段。
3. 如果存在 `previous.app`，可以用它恢复原安装位置；恢复前先确保当前额度工具已经退出。
4. 也可以从官方 Release 重新下载与处理器匹配的 DMG，手动替换应用。

完成恢复并确认应用可以运行后，再按需要清理旧更新目录。完整卸载时的检查项见[卸载与清理](UNINSTALL.md)。

## 手动更新

自动更新不可用或不希望使用时，可以：

1. 打开项目 [Releases](https://github.com/zz-zed/GPT-TouchBar-hud/releases) 页面。
2. 下载与 Mac 处理器匹配的 `arm64.dmg` 或 `x86_64.dmg`。
3. 退出正在运行的 GPT TouchBar HUD。
4. 打开 DMG，将新应用拖入 `Applications` 并替换旧版。
5. 启动新应用，从菜单确认版本和构建号。

升级会保留已有界面偏好。v0.1.30 中，未保存过“刘海常驻形态”的用户默认使用 Peek；已经保存的 Compact 或 Peek 选择保持不变。

## 信任和验证边界

当前发行包使用 ad-hoc 签名，没有 Apple 公证。应用会验证代码签名结构、包信息、文件大小和 SHA-256，但 SHA-256 文件与安装包来自同一个 GitHub Release。这些检查可以发现传输损坏或包内容不一致，不构成独立发布者签名或 Apple 公证。

更新信任边界是本项目 GitHub 仓库及 GitHub HTTPS 分发。v0.1.30 已完成双架构构建和仓库记录的自动化验证；macOS 11 真机运行，以及从每个受支持安装路径执行完整自动更新链路，仍属于发布记录中明确保留的验证边界。
