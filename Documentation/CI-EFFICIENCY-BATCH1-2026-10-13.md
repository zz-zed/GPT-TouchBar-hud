## 三轮耗时

单位为秒。CI 两架构均选择 Xcode 26.3 / Swift 6.2.4；本机补充对照使用 Swift 6.4，不与 CI 样本混合。下表“变化”为两组中位数之比。

| 环境 | 脚本 | 基线中位数 | 候选中位数 | 缩短 |
| --- | --- | ---: | ---: | ---: |
| arm64 | `test-hooks` | 60.330 | 29.197 | 51.60% |
| arm64 | `test-diagnostic-logging` | 123.201 | 120.454 | 2.23% |
| x86_64 | `test-hooks` | 97.006 | 86.081 | 11.26% |
| x86_64 | `test-diagnostic-logging` | 227.561 | 218.023 | 4.19% |
| 本机 arm64 | `test-hooks` | 61.557 | 46.572 | 24.34% |
| 本机 arm64 | `test-diagnostic-logging` | 161.106 | 149.258 | 7.35% |

逐轮 CI 样本如下，不能只引用最快轮次：

| 架构 | 轮次 / 顺序 | 核心基线→候选 | 诊断基线→候选 |
| --- | --- | ---: | ---: |
| arm64 | 1 / 先基线 | 65.632 → 28.309 | 118.454 → 107.771 |
| arm64 | 2 / 先候选 | 41.420 → 49.535 | 140.502 → 155.739 |
| arm64 | 3 / 先基线 | 60.330 → 29.197 | 123.201 → 120.454 |
| x86_64 | 1 / 先基线 | 107.394 → 86.081 | 462.909 → 243.478 |
| x86_64 | 2 / 先候选 | 97.006 → 113.677 | 227.561 → 218.023 |
| x86_64 | 3 / 先基线 | 85.665 → 48.890 | 212.425 → 174.320 |

两个架构在先候选的第二轮都出现核心脚本墙钟回退；ARM 诊断第二轮也回退。因此，三轮中位数支持继续保留这批减编译改动，但不支持承诺每次固定提速。尤其诊断整组的中位数改善较小。

每一对在同一 runner 上串行执行，三对顺序为基线→候选、候选→基线、基线→候选。两端使用独立的新源码快照与项目构建目录，不恢复 Actions 缓存；系统和 OS 缓存未清空。每个快照先运行核心脚本，再运行诊断整组，后者含该快照内的依赖构建，不等价于完整 CI 中已经复用依赖后的单步耗时。

预试跑发现原有诊断 fixture 假设第一次有预算的 poll 一定完成发现；旧编译方式也复现同一启动断言失败。现为同一真实引擎在最多 2 秒内完成启动协调，原 running ID 断言不变。所有正式基准两端都覆盖为相同 fixture，摘要记录其 SHA-256；失败的预试跑未计入收益。

## 后续批次边界

第一批单次完整 CI 已达到慢作业低于 15 分钟的目标，但三轮基准只覆盖两组改动脚本，不能据此承诺所有后续完整 CI 都低于 15 分钟。

本轮数据/界面两组在两个架构均只差 32 秒，暂不改动分组。后续优先试点同一作业内、参数完全一致的界面测试编译复用：`test-idle-performance.sh` 与 `test-design-layout.sh` 是可进一步验证的候选。`test-status-menu.sh` 使用 WMO，`test-hud-material.sh` 还显式指定 macOS 11 target，不能把它们无条件并入同一个编译产物。试点仍需独立测试进程与 UI 串行验证；跨运行缓存继续放在其后评估。

当前交付为第一批独立实现分支和验证记录，尚未合并 main 或发布应用。
