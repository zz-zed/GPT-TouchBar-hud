验证日期：2026-10-03。基线：`229d2919132e2c9cc31aa97133ce9495a11bf5ff`，对应 v0.1.38 后的 main。工作分支：`codex/task-lifecycle-validation`。

## 本轮结论

本机两份已结束会话在 19:39:46 收到旧预览服务器退出的 `item_completed`。原普通日志模式把它们重新计为执行中；Hooks 在缺少旧轮次历史的尾部回放中也会误判。修正后，两条路线在这两个样本上均不再增加执行中数量。

本轮统一了生命周期转换规则，保留现有两种读取方式及展示方式。尚未接入桌面宿主的运行时状态；等待审批、等待用户输入的独立状态也没有在缺少可靠事件时推测生成。

## 改动

- `HookCore/TaskLifecyclePolicy.swift`：两条路线共用事件分类和状态转换规则。明确的 `task_started` 可以开启任务；工具结果和 Token 更新只能维持已确认且未过期的同轮活动。
- `TaskStatusMonitor`：旧轮次工具事件不能更换当前轮次，无法归属轮次的事件不参与状态转换。首次读取历史、文件轮转及有界读取跳过内容时保留未知。监测启动后新发现的明确开始记录仍可计数。索引只纳入 `cli`、`exec`、`vscode` 主会话。
- `TaskStateReducer`：弱事件不创建轮次记录，也不覆盖终态或已失效的运行状态；同一 turn ID 的明确继续开始可更新轮次顺序。
- `TaskEvidenceResolver`：结束记录等待稳定 EOF 时，后来的工具/Token 记录不再把它覆盖掉。
- 回放脚本只读取本机日志，输出数量和读取字节数。原始对话、工具内容及日志文件没有复制到仓库。

## 回归覆盖

| 场景 | 验证结果 |
| --- | --- |
| 工具事件单独出现、旧轮次事件迟到 | 不创建或复活任务，不替换新轮次 |
| 已完成、已中断、待确认结束 | 工具事件不能改回执行中；结束记录仍能完成 EOF 核对 |
| Stop 后继续执行 | 已确认活动可继续，未制造成功完成 |
| 提交被阻止、回调重复或乱序 | 提交保持待核对；不重复计数、不覆盖更新证据 |
| 相同 turn ID 明确续跑 | 更新轮次位置，恢复正确的会话计数 |
| 重启、断连、休眠、过期 | 缓存和弱事件不重新证明实时执行；不制造成功 |
| 主任务与子代理 | 主会话计一次，索引中的子代理排除 |
| 长时间无输出 | 5 分钟仍保持已确认活动；30 分钟后转为未知，不视为完成 |
| 大文件、半条记录、轮转、读取失败 | 保持原有资源上限及中性展示 |

## 取舍与剩余验证

开始记录落在读取范围之外，或发生在监测恢复之前时，真实运行中的任务可能暂时不计数。工具结果不能弥补这个证据缺口。这是此次减少误报的明确取舍；普通日志模式继续使用已有中性外观，内部保留未知诊断。

本机此前未发现可供 HUD 旁观连接的桌面 App Server 端点，因此本轮没有引入独立 daemon 或恢复宿主会话。后续要减少恢复时漏计，优先验证同一宿主的运行时快照与状态通知。原始样本仅两个，不据此估算全局准确率、长期未知比例或能耗改善。

真实宿主 Hooks 投递、安装后的持续使用、Intel 和 macOS 11 运行验收仍未完成。本轮未修改用户 Hooks 配置、信任记录或正式安装。

设计依据延续本轮已核对的 [OpenAI Hooks 语义](https://learn.chatgpt.com/docs/hooks) 和 [App Server 状态接口](https://learn.chatgpt.com/docs/app-server)。其中 transcript 属于兼容证据，格式仍可能变化。
