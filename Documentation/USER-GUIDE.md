# 使用指南

[返回项目说明](../README.md)

本文适用于 GPT TouchBar HUD **v0.1.30 / Build 33**，介绍安装后的日常操作、各显示界面和设置项。额度、任务状态的数据口径见[数据与隐私](DATA-AND-PRIVACY.md)，更新行为见[更新与恢复](UPDATING.md)。

## 开始使用

安装包的最低构建目标为 macOS 11，但实际 macOS 11 运行尚未验收，ChatGPT / Codex 宿主客户端也可能要求更高版本。请先在系统 `/Applications` 中安装并登录 ChatGPT、Codex 或 GPT，再从 [Releases](https://github.com/zz-zed/GPT-TouchBar-hud/releases) 下载与处理器对应的安装包：

| Mac | 安装包 |
| --- | --- |
| Apple Silicon | 文件名以 `arm64.dmg` 结尾 |
| Intel | 文件名以 `x86_64.dmg` 结尾 |

打开 DMG，将 `GPT TouchBar HUD.app` 拖入 `Applications`。如果首次打开时系统提示“无法验证开发者”，可以运行 DMG 内的 `首次打开助手.command`，输入 `OPEN` 后按回车；也可以先尝试打开应用，再到“系统设置 → 隐私与安全性”选择“仍要打开”。应用目前使用 ad-hoc 签名且未经 Apple 公证，只应打开从本项目 Release 下载且由你信任的安装包。

应用作为菜单栏配件运行，不在 Dock 常驻。首次运行会在菜单栏显示状态，并注册当前用户的 LaunchAgent：

```text
~/Library/LaunchAgents/io.github.zz-zed.GPTTouchBarHUD.CodexLauncher.plist
```

之后 ChatGPT / Codex 启动时，额度工具会自动打开；宿主完全退出后，额度工具也会结束。如果在宿主仍运行时手动退出额度工具，本轮宿主会话不会再次自动拉起，宿主完全退出后会解除这次手动退出状态。

从旧版升级时，应用会迁移 HUD 外观和 Touch Bar 常驻设置，停用旧 LaunchAgent，并兼容旧版的手动退出状态。

## 显示界面

![菜单栏、桌面浮窗和可选 Touch Bar 的使用场景](../Marketing/readme-hero-v4.png)

主图为基于原生界面制作的展示示意，使用演示数据；字形、间距和系统控件以下方原生截图与当前界面为准。

### 菜单栏

菜单栏图标会随任务状态变化。菜单栏内容可以选择“自动 / 仅图标 / 单额度 / 完整额度”：

- **自动**：刘海面板或桌面浮窗可见时只显示图标；当前面板隐藏后显示一项主要额度。
- **仅图标、单额度、完整额度**：保持所选内容，不随面板是否可见而改变。

完整额度模式的示例为 `5h 85%  W 80%`。如果账号没有 5 小时窗口但提供完整重置次数，则可能显示为 `重置3  W 96%`；实际项目只取决于账号返回的数据。

点击菜单栏后，顶部会汇总额度、任务状态、重置或到期时间、昨日/累计 Token、点数和更新时间。下方可以刷新、显示或隐藏当前面板、选择显示形式和菜单内容、控制 Touch Bar、打开设置、检查更新或退出。

![菜单顶部原生摘要](../Marketing/readme-native-menu-summary.png)

### 刘海融合面板

有效刘海区域上提供三种状态：

- **Compact**：静止时只显示两侧指示器，悬停后进入 Peek 查看额度。
- **Peek**：静止时常驻显示额度与重置预览。没有保存过该偏好时，v0.1.30 默认使用 Peek。
- **Expanded**：点击面板后展开，可切换额度、活动和用量页面，并使用刷新、设置、隐藏和收起操作。

已保存的选择会继续保留：旧偏好值 `false` 对应 Compact，`true` 对应 Peek。退出悬停或收起详情时，面板回到所选的静止形态。任务状态变化不会自动展开面板。

![Compact 静止态](NotchIsland/evidence/synthetic-compact.png)

![Peek 额度预览态](NotchIsland/evidence/synthetic-peek.png)

![Expanded 详情态](NotchIsland/evidence/refined-synthetic-expanded.png)

这些图片来自合成屏幕几何和演示数据，用于核对界面状态，不代表实体刘海环境已经验收。面板按真实渲染轮廓处理点击；摄像头区域与透明圆角让点击穿透，发光和阴影不扩大可点击范围。

### 桌面浮窗

桌面浮窗以单行显示任务状态与额度，并根据内容自动调整宽度。它只保留刷新按钮；隐藏、显示和设置操作从菜单栏进入。额度重置时间、点数及昨日/累计 Token 保留在菜单摘要中。

![桌面浮窗原生排版](../Marketing/readme-native-quiet.png)

### Touch Bar

配备 Touch Bar 的机型默认在左侧应用区域常驻显示额度条，切换到其他 App 后仍会重新呈现。右侧系统控制条保持可用；展开系统控制条时会暂时覆盖 Token，收起后恢复。隐藏刘海面板或桌面浮窗不会影响 Touch Bar 常驻。

在设置中关闭“Touch Bar 常驻”后，应用会释放系统级项目；普通的跟随焦点展示仍可使用。此能力运行时检查 AppKit 的私有系统模态接口，未来 macOS 版本可能改变其行为。

![Touch Bar 重置卡、周额度和点数](../Marketing/readme-native-balanced-reset-alignment.png)

## 设置

从菜单栏选择“设置…”或按 `⌘,` 打开独立设置窗口。

| 标签页 | 可调整内容 |
| --- | --- |
| 通用 | 显示形式、显示或隐藏当前面板、刘海常驻形态、菜单栏内容、语言、任务状态提示。 |
| 外观 | 桌面浮窗颜色、背景与文字不透明度，并提供实时预览。 |
| Touch Bar | 开启或关闭跨 App 常驻；没有相应硬件时显示为不可用。 |
| 实验 | 查看 Hooks 配置计划，并在明确应用后启用实验。 |
| 更新 | 开启或关闭自动检查、查看状态和手动检查。 |

“信息语言”只影响额度与任务信息的文字、日期和数字单位，导航与设置保持中文。中文 Token 显示使用“个 / 万 / 亿”，英文使用 `K / M / B / T` 紧凑单位。

### 显示形式与初始状态

显示形式可以选择自动、刘海融合或桌面浮窗：

- 未保存显示形式时使用自动模式。
- 有有效刘海且未保存面板可见性时，首次运行会显示刘海面板。
- 没有刘海时，桌面浮窗首次运行默认隐藏。
- 手动选择的显示形式和显示/隐藏状态会在重启及屏幕变化后保留。
- 所选刘海模式暂时没有有效几何时，会回退桌面浮窗，但不会改写用户选择；macOS 11 也使用这一回退。

“刘海常驻形态”提供“静止态 Compact”和“额度预览态 Peek（默认）”。Compact 适合只在悬停时查看额度，Peek 会让额度预览常驻。更改该选项不会重置面板可见性、轮廓、动画或点击行为。

### 任务状态提示

“显示任务状态（实验性）”默认开启。菜单栏用蓝色表示执行中、绿色表示最近完成、灰色表示状态未知；关闭任务提示或空闲时使用系统中性色。Touch Bar 会在图标右下角显示蓝色数量、绿色 `✓` 或灰色 `?`，桌面浮窗打开时也会显示同一摘要。

执行中的轻微呼吸动画会在任务结束或界面隐藏时停止；开启系统“减少动态效果”后保持静态。任务变化不会自动打开桌面浮窗或展开刘海。状态口径和限制见[数据与隐私](DATA-AND-PRIVACY.md#任务状态的读取与判断边界)。

### Hooks 实验

Hooks 默认关闭。打开“设置 → 实验”只会显示待应用的配置计划，不会写入配置或启用监测。只有审阅后明确点击应用，应用才会安装稳定 helper 并修改 Hooks 配置。新建或变更的 Hook 可能需要在宿主中重新信任并重新打开任务。

Hooks 用于触发状态核对，额度和 Token 数据来源不变，任务状态仍会有界读取本机索引与近期日志。详细行为、覆盖范围和清理边界见 [Hooks 实验说明](HOOKS-EXPERIMENT.md)。

## 常用菜单操作

| 菜单项 | 用途 |
| --- | --- |
| 刷新额度 | 立即刷新额度，并在防抖允许时刷新 Token；刷新中不会重复执行。 |
| 显示状态面板 / 隐藏状态面板 | 按当前显示形式打开或隐藏面板，选择会保存。 |
| 收起详情 | 从 Expanded 返回所选刘海静止形态。 |
| 显示形式 | 选择自动、刘海融合或桌面浮窗。 |
| 菜单栏内容 | 选择自动、仅图标、单额度或完整额度。 |
| Touch Bar 常驻 | 开启或关闭跨 App 常驻。 |
| 设置… | 打开设置窗口。 |
| 新版本提醒 / 检查更新… | 查看可用版本或手动检查。 |
| 退出 | 结束应用，并在当前宿主会话中阻止自动重新拉起。 |

## 已知边界

- 应用依赖 ChatGPT / Codex 随附的本机 `codex app-server`。宿主路径或本地数据格式变化后可能需要适配。
- 刘海轮廓与交互已有合成几何和原生 AppKit 验证；实体刘海贴合、全屏应用、菜单栏自动隐藏、多屏切换、热插拔和睡眠唤醒仍需在真实设备上核对。
- Touch Bar 常驻依赖运行时检查的私有 AppKit 能力，系统升级可能影响可用性。
- 任务状态是实验性提示，不应作为任务成功、审批状态或完整进度的唯一依据。
