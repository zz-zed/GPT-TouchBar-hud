## 组件设计

名称可按现有命名调整，但以下职责需要明确分开。

| 组件 | 责任 | 关键约束 |
| --- | --- | --- |
| LifecycleStreamDecoder | 流式提取 event_msg 和 session_meta 的允许字段 | 不保存正文；处理转义、字段顺序、嵌套、跨块 UTF-8 与半行；正文伪事件无效 |
| TaskJournalReader | 验证文件身份，从已提交位置连续读取 | 分开 fetchedOffset 与 committedOffset；只在完整记录边界提交；不跳到尾部 |
| TaskInventory | 分页发现、身份验证、来源分类、待处理队列 | 任务总库存与每轮读取配额分离；活跃记录保留；缺项不等于结束 |
| TaskActivityEngine | 统一事件排序、状态转换、计数与完成去重 | thread 去重、turn 排序、代次隔离；终态不能被弱事件复活 |
| TaskCheckpointStore | 原子保存最小状态与读取断点 | schema 版本、原子写、恢复校验、容量约束；无正文和诊断导出隐私泄漏 |
| TaskObservationSink | 发出生产状态与读取边界事件 | 白名单值对象、进程内匿名别名、稳定快照编号；不新建第二套诊断存储 |
| TaskMonitoringCoordinator | 管理开关、宿主生命周期与来源接入 | 旧回调失效、关闭停止 I/O；四个显示端使用同一快照 |

核心逻辑优先放在现有 HookCore 可测试模块中，避免多个 Swift 编译入口重复实现。遵守当前 Swift tools 5.8 与 macOS 11 的项目基线，不顺带迁移 Swift 6 并发模式或引入无必要依赖。使用 write-swift 技能，但语言和 SDK 兼容性以仓库要求为准。

## 读取和调度细节

每次调度从原位置继续读取，并设定每文件字节、全局字节和时间预算。预算只影响完成速度，不改变生命周期。按任务轮转；有积压则短间隔继续，空闲退回低频检测；所有工作都应支持取消与连接代次校验，不能在主线程做 SQLite、文件读取或解析。

捕获本次待处理范围的文件长度作为同步目标，追加内容安排到后续轮次，避免无限追逐变化的 EOF。不能在未处理完的历史中逐条发布运行与完成闪烁；一个同步批次的最终状态原子发布。持续积压保留最后已知状态及内部时效，记录延迟，不声称旧数是精确实时数。

大行不能用简单截断或搜索字符串判断。流式解析器跳过无关值、只累计有限允许字段；对无法分类、非法或超出语义字段限制的记录记录固定原因。大 task_complete 与大 session_meta 也必须支持提取关键字段。解析深度等保护上限需明示且有测试，超限不能静默转成无任务。

索引采用稳定分页键和周期性完整对账；若 updated_at 在分页中变化，使用边界重叠与身份去重等可测试机制防漏。不得用 OFFSET 加可变排序而假定覆盖完整。活跃任务优先处理，非活跃历史逐步发现；没有完整遍历，不设置完整覆盖标记。

## 生命周期与恢复细节

保留明确 start 才能建立当前执行的保护。仅接收同轮次的辅助执行事件，结束后的工具和 Token 事件不激活任务；旧轮次结束不能结算新轮次。只有可信 start 或受验证的宿主当前状态能重新建立当前执行。

持久化需要同时保存状态、committedOffset、文件身份与代次、记录边界锚点、完成去重信息。崩溃在读写之间发生时，通过重读和幂等恢复；不能出现 offset 已前进但状态没保存。验证路径、文件所有权和允许目录，继承现有 Hooks 安全约束。

宿主退出、HUD 重启、休眠和连接重建分别建模。恢复保留 last-known 与来源/时效，历史 active 不自动当作 current active。待核对不会自动转成功，不能靠超时制造精确零。仅因恢复暂时不确认当前执行与因缺陷丢失已确认执行必须分别测试和诊断。

首次安装或无可信断点时，历史重建应分批进行，不扫描整个历史后才允许新任务工作。新任务和已知活动文件优先，重建低优先级、公平且可取消；不得宣称历史 start 本身证明当前执行。

## 与诊断工作的接口

另一会话正在实现匿名任务轨迹、读取边界、任务排除与显示快照关联。只读查看其方案和已有类型，优先复用确定的接口；不在另一工作树编辑，不自动导入其未提交实现。

本任务负责生产真实事件，诊断任务负责记录、轮转、预览和导出。若基线尚无诊断实现，提供类型化 sink 和内存测试 sink，并交付字段映射及最小接入说明；这可以独立完成，不把诊断模块合并当作前置条件，也不另建 ZIP/设置页面/日志存储。

事件最少包含：进程内任务别名、源模式、扫描/快照编号、前后阶段、加入或退出计数的固定原因、文件代次、读取前后位置、读取和积压字节、覆盖状态、主线程接受或丢弃与实际提交的显示摘要。进程内原始 ID 映射不进入诊断包；持久 checkpoint 的内部身份字段也不自动导出。

普通模式继续遵守既有“不显示未知问号、诊断行或诊断 tooltip”的决策。可以记录内部状态，不借此次改造增加 UI 异常提示。
