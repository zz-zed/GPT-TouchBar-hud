# 系统命令与公告后台处理

2026-10-06。基线为 `d2a9e0345b754ef6c48145d2bceea5a9ed46ddd0`，即 v0.1.40 发布记录提交。本批完成自动启动设置的后台执行、命令超时，以及公告解析和缓存读写的后台处理。代码为本地未提交改动，版本元数据仍为 0.1.40 / Build 43。

## 行为变化

- 自动启动注册、移除和核验由串行后台队列执行，结果回到主线程。偏好仍只在系统操作核验成功后保存；设置正在处理时暂时禁用重复操作，失败后恢复输入并显示已保存的选择。
- 每条 `launchctl` 命令等待上限为 5 秒。超时先发送终止信号，0.25 秒后仍存活则终止本次创建的进程，再有限等待退出。输出使用私有临时文件收集，返回最多 64 KiB，避免管道容量或继承管道的 EOF 拖住等待；临时文件在结束后清理。
- 公告 HTTP 响应解析由后台队列执行；时钟值在主线程捕获，结果汇总和界面更新仍在主线程。取消会跳过尚未执行的解析，并拒绝晚到的解析结果。
- 缓存读取、JSON 解码、编码和原子写入由串行 I/O 队列执行。内存状态留在主线程，写入使用提交时的值快照，按顺序执行；重复标记已读且状态未变时不再写盘。网络首次检查等待旧缓存和通知去重记录加载完成，兼容迁移也先完成写盘。
- 界面可以先显示新预告，提醒必须等对应去重记录写盘成功。写盘失败、停止监测、预告被替换或用户已读时，晚到的成功回调不会发送过时提醒。应用退出时异步等待已排队的缓存写入，最多 3 秒，避免磁盘异常无限阻止退出。

历史 feed/timeline 仍只作为内部证据；可见预告与通知继续由当前权威信号驱动，未知与确认空结果的区别保留。

## 验证边界与后续

命令测试只操作自有临时进程和隔离注册目录，公告网络及通知使用注入依赖，没有修改本机实际 LaunchAgent 或已安装应用。未运行整机 CPU、内存、唤醒或功耗基准，因此不能据此量化性能收益。真实 macOS 11、Intel 运行、休眠唤醒、正式安装路径的升级重启及退出等待仍需实机验收；磁盘长时间卡住并超过退出等待上限时，尚未完成的缓存写入可能无法保存。

自动启动检测频率、任务监测调度、SQL 查询成本、核心模块与测试入口收敛、协调层拆分及安装后期故障注入未包含在本批改动中。

实现沿用 macOS 11 支持的 Foundation/Dispatch 接口，依据 Apple 的 [Process 完成回调](https://developer.apple.com/documentation/foundation/process/terminationhandler)和[串行队列执行顺序](https://developer.apple.com/documentation/dispatch/dispatch-queue?changes=la)，未提高部署目标或引入新运行时依赖。
