# 数据、刷新口径与隐私

[返回项目说明](../README.md)

本文说明 GPT TouchBar HUD **v0.1.30 / Build 33** 读取哪些数据、如何解释和刷新这些数据，以及在本机和网络上留下哪些状态。

## 数据来源

应用依次查找 ChatGPT / Codex 随附的本机 `codex` 程序：

```text
/Applications/ChatGPT.app/Contents/Resources/codex
/Applications/Codex.app/Contents/Resources/codex
/Applications/GPT.app/Contents/Resources/codex
```

找到后，以子进程启动：

```text
codex app-server --listen stdio://
```

应用通过本机 stdio JSON-RPC 读取账号数据，不抓取网页，也不要求填写 API Key。具体来源如下：

| 展示内容 | 数据来源 | 口径 |
| --- | --- | --- |
| 5 小时和周额度 | `account/rateLimits/read` | 根据服务返回的窗口时长识别；不会把同一个周窗口复制成 5 小时额度。 |
| 完整重置次数 | `account/rateLimits/read` 的 `rateLimitResetCredits` | 显示可用数量和最早到期时间。 |
| 点数余额 | `account/rateLimits/read` 的 `credits.balance` | 为零、无限或缺失时隐藏。 |
| 昨日 Token | `account/usage/read` | 用当前系统日历匹配昨日桶；服务端全局时区未公开承诺。 |
| 累计 Token | `account/usage/read` | 直接使用服务返回的累计值，不用有限时间桶相加。 |
| 任务状态 | 本机 Codex 任务索引与近期日志；可选 Hooks 信号 | 仅用于本机实验性状态提示，不代表账号内所有远程任务。 |

应用本身不直接读取或保存宿主登录凭据。账号或工作区变化主要依赖宿主通知触发同步；如果显示没有及时变化，可以从菜单栏手动刷新。

## 刷新和失败显示

- 额度每 60 秒刷新，并响应 app-server 通知。
- Token 每 5 分钟刷新一次。
- 手动 Token 刷新的最短间隔为 10 秒，避免连续请求。
- Token 失败后按 5、10、20、30 分钟重试。
- 短暂失败时保留最近一次 Token，并以 `*` 标记为旧数据；没有可用数据时显示 `--`。
- 更新检查使用独立计划，不属于额度或 Token 刷新；详见[更新与恢复](UPDATING.md)。

## 任务状态的口径

“显示任务状态（实验性）”默认开启，默认使用日志模式：

- 只查看本机最近 32 个未归档 Codex 任务。
- 首次参与判断的任务必须在最近 30 分钟内有日志更新；更早的历史任务不会影响当前状态，这不表示它们已被确认结束。
- 监测期间继续有日志更新的任务会保留在判断范围中。
- 新任务通常在 10 秒内发现；已知任务每 2 秒检查一次新增日志。
- 单个文件每次最多读取 256 KiB。
- 执行中优先显示。正常完成提示保留 30 秒；明确中止回到空闲，不显示完成。
- 执行中任务连续 30 分钟没有新事件后才降级为未知，以兼顾长时间运行命令和遗留状态。
- 日志格式不兼容、事件缺失或读取失败时显示 `?`，不会影响额度读取。

这些状态不能判断等待审批、等待输入、失败原因、进度百分比或整个目标是否完成。“本轮完成”只表示当前观察到的一轮结束。该功能依赖未公开承诺稳定的本机记录格式，宿主升级后可能需要适配；关闭开关会停止任务日志读取。

## 按显示现象排查

| 现象 | 含义与建议 |
| --- | --- |
| 额度或 Token 显示 `--` | 当前没有可确认的数据，不代表数值为零。确认 ChatGPT / Codex 已登录且正在运行，再从菜单执行“刷新额度”；持续缺失时检查宿主内置 app-server 是否可用。 |
| Token 数字后有 `*` | 当前刷新失败，界面保留上次数据。等待自动重试或稍后手动刷新；不要把它当作最新统计。 |
| 任务状态显示 `?` | 日志证据、Hooks 覆盖或连接状态不足，无法确认当前任务数。它不表示零任务、任务完成或失败；可关闭实验性任务提示。 |
| 只有周额度，没有 5 小时额度 | 应用只展示接口实际返回的窗口。只有周额度不一定是异常，也不会把周窗口复制成 5 小时额度。 |
| 切换账号或工作区后仍显示旧值 | 同步主要依赖宿主通知。确认目标账号已完成切换，再手动刷新；短暂失败时旧 Token 会带 `*`，不要按旧值判断新账号。 |

## Hooks 实验

Hooks 默认关闭。只有在“设置 → 实验”审阅计划并明确应用后，才会写入 Hooks 配置和安装稳定 helper。启用后：

- Hooks 信号用于提示应用核对任务生命周期；应用仍会有界读取本机任务索引和近期日志。
- 状态区分执行中、已提交待核对、未知、覆盖范围和连接健康。
- 覆盖不完整时保留 `?` 和原因，不把连接正常解释为全量覆盖或精确零任务。
- 新完成提示约 4 秒后消失；刷新、隐藏后重开不会重播，同一轮继续执行会撤销完成提示。
- 额度与 Token 的来源、刷新方式不变。

当前没有关于真实宿主任务准确性、端到端延迟或长期能耗收益的验收结论。配置、权限、资源上限和清理方法见 [Hooks 实验说明](HOOKS-EXPERIMENT.md)。

## 本机保存的数据

应用不会把当前额度或 Token 历史建立成自己的数据库；当前展示值保留在运行内存中。为维持用户选择、启动联动、更新和可选实验，以下数据可能保存在磁盘：

| 位置或类型 | 保存内容 |
| --- | --- |
| macOS `UserDefaults` | 界面、任务提示、自动更新选择，以及更新检查的时间、失败和可用版本状态。 |
| `~/Library/LaunchAgents/io.github.zz-zed.GPTTouchBarHUD.CodexLauncher.plist` | 随 ChatGPT / Codex 启动额度工具的当前用户 LaunchAgent。 |
| 应用支持目录 | 当前宿主会话的手动退出标记；启用 Hooks 后还包含稳定 helper。 |
| 应用同级 `.GPTTouchBarHUD-update-<随机标识>/` | 用户确认安装更新后产生的 staging、`install.log`、`previous.app` 和失败恢复材料；备份不会自动删除。 |
| `$CODEX_HOME/hooks.json` 或 `~/.codex/hooks.json` | 仅在用户应用 Hooks 配置后写入；修改前保留带时间戳的备份。 |
| `~/.gpt-touchbar-hud-hooks/` | 启用 Hooks 后使用的私有 socket、锁和 `state.json` 生命周期元数据缓存。 |
| `~/Library/Application Support/GPTTouchBarHUD/Hooks/HookEmitter` | 启用 Hooks 后安装的稳定 helper。 |

关闭 Hooks 会恢复日志模式，但不会自动删除已经应用的配置、备份、helper 或运行目录。删除 App 也不会自动完成这些清理；请按[卸载与清理](UNINSTALL.md)处理。

## 网络活动

应用自身的网络用途限定为更新检查和经用户确认后的更新下载：

- 自动更新会访问本项目公开 GitHub Release API；普通读取失败时可回退到最新 Release 页面。
- 更新请求的 `User-Agent` 含当前应用版本，不携带账号、任务或本机日志内容。
- 发现版本不会自动下载；只有用户点击“安装并重启”后才下载对应架构的资产和校验文件。

额度与 Token 请求由本机 `codex app-server` 使用现有宿主登录态完成。GPT TouchBar HUD 不保存密码、API Key、授权码或访问令牌，也不上传本机任务日志。

## 内容边界

默认任务模式只读取索引和有限的近期日志片段，用于推断生命周期状态；不会在界面显示、另存或上传对话正文。Hook helper 只传递允许的生命周期元数据，不转发或持久化提示词、回复、工具参数、工作目录或 transcript 路径。

如果不希望应用读取本机任务索引和近期日志，可以在“设置 → 通用”关闭“显示任务状态（实验性）”。如果已经应用 Hooks，还需要按照专题文档中的独立流程清理其配置和 helper。
