# 更新下载与安装进度验证记录

日期：2026-10-03。源码基线：`main` / `5e1212a`；本次为本地优化，应用版本保持 `0.1.37` / Build `40`，未发布或替换正式安装。

## 实现

确认“安装并重启”后显示约 480 点宽的原生非模态更新窗口。下载使用 `URLSessionDownloadDelegate` 上报真实字节，最多约每秒 4 次刷新数值，阶段变更立即发布。总量来自 Release 资产大小或经过检查的 HEAD 响应；实测速率有足够样本后才显示，下载 100% 不表示安装完成。

后续显示完整性检查、读取安装包、检查身份与签名、准备新版、等待旧进程退出、保留旧版、替换、等待启动等步骤，使用活动指示器。保留原有来源、大小、SHA-256、版本、架构、最低系统版本和代码签名检查。

临时助手是当前可执行文件在本次私有更新目录中的副本，私有启动模式在主应用的单实例入口之前分流，不构造 HUD 服务或注册启动项。主应用、助手和安装脚本分别写入原子状态文件，并核对随机会话标识。旧进程退出后助手继续运行，提供临时菜单入口。

新版完成核心初始化后，核对会话、安装路径、应用身份和预期版本，写入带进程号的启动确认。安装脚本与助手只接受对应版本的有效、存活回执；启动请求成功与确认超时都不等于完成。助手收到确认后显示完成，约 3 秒后退出；隐藏的窗口不会重新弹出。

下载期间可取消，失败可从零重试；各尝试使用不同标识与文件名，迟到的网络回调不能覆盖新的状态。关闭、Escape 与“后台继续”仅隐藏窗口。菜单与设置可重开同一会话，取消或失败后恢复检查更新。

文件替换失败或启动请求失败时尝试恢复旧版，区分原应用未替换、旧版已保留、已确认恢复和需人工核对。仅启动等待超时不会自动回滚，以免替换可能正在运行的新版。恢复到不支持本次回执协议的旧版本时，会明确保留“已放回但尚未确认启动”的结果，需用户打开并检查。

主要实现：[下载与准备](../Sources/AppUpdateInstallation.swift)、[字节回调](../Sources/AppUpdateDownload.swift)、[状态通道](../Sources/AppUpdateProgressChannel.swift)、[原生窗口](../Sources/AppUpdateProgressWindowController.swift)、[临时助手](../Sources/AppUpdateProgressHelper.swift)、[安装脚本](../Resources/install-update.sh)。

## 解锁后的桌面检查

屏幕解锁后已补做原生回归与桌面窗口操作。进度助手本身是临时可执行文件，桌面自动化不能直接定位该进程；为窗口检查，在本次 `build` 目录创建仅包含同一份状态通道、窗口与助手源码的测试应用。该应用无普通 HUD 初始化、启动项或安装功能。已构建候选可执行文件的私有入口与生命周期另由上述二进制探针验证。

| 桌面场景 | 结果与证据 |
| --- | --- |
| 下载显示 | 实际窗口显示 40%、40 MB / 100 MB、2 MB/s；数值为测试夹具，不代表真实下载 |
| 取消与重试 | 点击按钮生成匹配本次会话的 `cancel` / `retry` 命令；取消、失败和从 0% 重试的状态显示正常。发现取消副标题仍显示下载中，已改为“下载已停止”并通过回归 |
| 收起与重开 | “后台继续”、Escape、关闭按钮收起窗口；助手仍存活，操作文件未变为取消。发送同一会话的显示命令后可重开 |
| 校验与安装 | 显示当前步骤与活动指示器，没有安装百分比或取消按钮 |
| 旧进程退出 | 仅结束本次夹具的模拟旧进程；核验旧进程已退出，助手与模拟安装进程仍存活，安装窗口继续显示 |
| 等待启动 | 启动中与启动未确认分别显示；错误版本回执不会产生成功提示 |
| 迟到的正确回执 | 收起启动待确认窗口后，助手仍存活；写入匹配会话、目标版本与存活进程的回执后，约 3 秒正常退出。隐藏窗口不会因状态更新重开的行为另有原生回归断言 |
