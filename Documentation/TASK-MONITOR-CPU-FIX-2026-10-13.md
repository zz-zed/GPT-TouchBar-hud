# 任务监控 CPU 修复与验证

2026-10-13。分支 `fix/task-monitor-cpu`，基线 `947641c`（v0.1.43 / Build 46）。原工作区存在其他未提交改动，因此本次在独立工作树实施。本文保留第一阶段固定输入的独立监控进程对照；后续已备份并替换安装包，增加任务重启恢复修复。当前安装状态、整应用 CPU 和真实任务验证见 [安装后验证](TASK-MONITOR-INSTALLED-VALIDATION-2026-10-13.md)。本文关于重启后要求新 start 的描述仅代表第一阶段行为，已由后续恢复修复取代。

## 问题与修复

本机正式 App 的 30 秒测量为单核 CPU 24.6%～26.3%，平均约 25.3%。用户提供的采样主要落在任务引擎的日志读取与状态缓存编码。缓存有 296 个会话，其中 269 个路径不可读。

此前读取失败保留 `needsRead`，使引擎持续声明有积压，控制器在每轮工作结束 50 ms 后再次轮询。每次失败还无条件标记缓存需要保存；即使最终内容相同，仍会编码整份约 403 KB 的状态作比较，发生变化时再编码一次用于写盘。

本次修改：

- 读取失败与可继续读取的数据积压分别调度。历史日志采用 1、2、4、8、16、30 秒退避，最长间隔 30 秒；曾确认运行的任务每秒重查。失败任务仍保留未知状态、最后已知状态与覆盖缺口。
- Hook 提示、索引条目变化及唤醒立即撤销对应退避。活动任务优先、公平扫描、新任务发现、1 秒普通轮询与真实积压的 50 ms 调度继续生效。
- 重复失败不再无条件使缓存变脏。缓存先比较结构化内容，相同时跳过编码，变化时只编码一次；集合顺序不会引发重复写盘。原子替换、容量检查与同步落盘保留。
- 新增或更新的索引元数据也会标记持久化；暂停、停止和重新观察时的候选状态变化继续保存。

仅调整读取调度和持久化。生命周期仍要求明确开始事件；工具/Token 事件不能制造或复活运行状态，缺失日志不能推定完成，重启或唤醒后的旧 active 仍按既有观察代次规则核对。无 Hook、无索引变化的历史路径重新出现，可能等待最长 30 秒；已有运行证据的任务保留 1 秒重查。

## CPU 与更新时效

通过 `bash scripts/benchmark-task-monitor-cpu.sh 947641c` 执行。脚本只读原始数据，复制到忽略的私有构建目录，再为每个进程克隆冻结输入。原始日志和正式状态缓存不写入。原始副本含私人会话内容，不进入提交；提交的 JSON 只有统计与验证摘要。

输入为 296 个缓存会话、719 条索引、27 份有效日志（229,255,588 字节）、269 个缺失日志。四份输入的日志摘要相同。使用优化编译的生产 `TaskEngineController`、`DiagnosticTaskEngineTrace` 和 `DiagnosticRecorder`，诊断开启。每轮预热 3 秒，随后测量 30 秒进程 CPU，顺序为旧—新—新—旧。

| 运行顺序 | 单核 CPU | 30 秒轮询次数 | 文件读取尝试 | 实际新增读取字节 |
| --- | ---: | ---: | ---: | ---: |
| 旧版 1 | 29.38% | 325 | 10,380 | 0 |
| 修复版 1 | 2.66% | 26 | 832 | 0 |
| 修复版 2 | 2.52% | 26 | 832 | 0 |
| 旧版 2 | 29.27% | 322 | 10,304 | 0 |

平均 CPU 从 **29.32% 降至 2.59%**，相对下降 **91.18%**。修复版两轮均没有快速积压轮询，读取失败数始终为 269，未通过删除会话或隐瞒失败降低工作量。采样进程峰值 RSS：旧版约 28.56～29.19 MiB，修复版约 28.55～28.73 MiB。

每轮测量后，向私有副本新增会话，并依次写入开始、完成、新轮次开始、中断。四轮均正确识别所有阶段。修复版八次交付延迟为 **0.54～1.09 秒**；旧版为 0.09～1.43 秒。修复版恢复普通 1 秒轮询，因此完成事件不会再因缺失历史日志而偶然享有高频轮询。

完整统计、输入与源码摘要见 [结构化验证记录](validation/task-monitor-cpu-2026-10-13.json)。原始证据位于本工作树 `build/task-monitor-cpu/20261013-153836.noindex/`。

## 正确性验证与适用范围

- 修复前，新增重试测试产生 7 个失败问题，复现不可读历史日志造成快速轮询与重复尝试。
- `bash scripts/test-hooks.sh`：107 项测试、14 个套件通过，包含新增退避、Hook/索引变化、65 个缺失日志下的实时生命周期、睡眠观察代次、部分数据积压与文件恢复测试，以及既有大日志、安全、乱序和恢复回归。
- `bash scripts/test-task-status.sh`：44 项检查通过。
- `bash scripts/test-task-reliability.sh`：196 项检查通过，覆盖两种模式、并发任务集合、公平读取、消费与停止后的取消。
- `bash scripts/test-hook-integration.sh`：默认关闭、未就绪状态及代次隔离检查通过。
- Shell/Python 语法、Git 空白检查通过。独立 arm64 App 构建与签名结果另见结构化记录。

本结果是当前机器上生产监控链路的短时对照，不含 AppKit 展示和网络额度轮询。正式 App 替换后的整进程 CPU、长期能耗、Intel 与 macOS 11 实机尚未验证。试用包保留 v0.1.43 / Build 46，仅用于本地验证，不是正式发布。
