## 已实现

- 保留两份工作流、29 条直接回归入口及原分组；沿用已有核心构建图、两个 UI fixture 的共享编译与计时。
- 集中维护五档位、保守路径分类和所需任务；普通 PR 为三项 ARM macOS 任务，完整档位仍为六项双架构任务。README 文档档位不运行 macOS。
- 新增 `CI Gate`，按具体子任务核对本 run/attempt，失败、缺失、跳过、取消、重复或状态不可取均拒绝。
- 发布独立要求七个核心任务，兼容没有新 Gate 的历史完整运行。产物名称、三个根文件及 manifest 协议保持不变。
- 同 PR 取消旧运行；PR 的路径过滤移入工作流；`ci:full` 与 `CI_FORCE_FULL_PR=true` 只增加检查。
- 离线规则在 Ubuntu source 中集中执行一次；构建计时单独上传；一级发布标题改为警告，原文与来源校验保留。
- 普通 PR 实际编译生产 App、Helper，校验签名与架构，并在隔离副本上测试首次打开；完整档位直接打包，不额外先构建一次。

## 安装器 fixture 修复及边界

本地原 fixture 失败于 `backup-failure: actual execution stages recorded`，缺少 `oldProcessExitObserved`。既有第三批探针已经记录冷启动复制子进程被生产 0.25 秒 watchdog 终止（137）；本次已加载 helper 的独立探针退出 0，说明成功运行不能证明冷启动稳定。

生产 watchdog 被提取为小型可替换函数，实际仍 sleep 0.25 秒后终止诊断子进程。正常事件覆盖 fixture 将这项 OS 调度边界控制为 5 秒，使用真实 CLI，保留所有原有场景、退出码、事件、来源、安全性和 8 秒总期限断言；故障与 10 秒挂起场景继续使用生产 watchdog，新增挂起场景小于 4 秒的断言。修复后一次执行通过 139 项检查，覆盖全部 12 个场景。没有预热、自动重试、忽略失败或削减事件断言。

这是对不稳定 fixture 的修复，不是生产诊断保证。生产仍允许 best-effort 事件因期限丢失；本次未延长生产期限，也未重启诊断重分组实验。

## 远端验收与性能状态

本分支的远端完整运行在提交后启动，最终状态和 run/attempt/commit 将补入本记录。新的 docs/pr-standard 工作流调度尚不能在 main 未具备新策略时通过只改文档的 main PR 独立演练。

结构上普通 PR 的 macOS 任务从六项降至三项、默认两份 DMG 降至零份；这不等于耗时减半。此前共享 UI 编译已有每架构三对有效样本，本次沿用同一实现；不能把旧样本当作本次所有新流程的计时。没有宣称新的整体流水线 30% 改善。三对新跨架构样本、排队到 Gate 的测量以及 main 同 SHA 恢复演练属于后续验收，需分别记录，不伪装成已完成。
