# 更新提醒与 API 故障验证

日期：2026-09-28。本文件记录 v0.1.36 发布前的本地验证。当时的测试包保留第一轮迭代的功能，且沿用 0.1.35 / Build 38 标签；该开发包与同号正式包不同。

## 交付行为

采用方案 B：菜单栏独立蓝色 ↑、菜单顶部带版本号的原生更新入口、每个新版本一次无声系统通知。顶部入口保留方向键、Enter 和辅助功能操作；任务图标、颜色和额度含义不变。

通知默认启用，独立于自动检查。后台只读取权限，尚未授权时由用户在设置点击“允许系统通知”；没有权限或处于专注模式时，菜单入口仍可见。点击通知打开版本说明，确认安装后才下载、校验和重启。

“稍后”保留入口；“跳过此版本”清除该版本提醒。跨重启记录已处理的最高版本；已有缓存、手动结果、关闭提醒或无权限期间的旧版本不补发。上游 Latest 回退时，所有入口同步采用父级采纳的版本，同时清除先前通知，不再主动通知已处理的低版本。

## GitHub API 不可用时的结论

**API 单独故障时，可以通过 Release 页面和附件直链继续更新。所有 GitHub 分发路径同时不可用时，无法完成更新。**

| 故障或步骤 | 行为与验证 |
| --- | --- |
| API 403 限流、429、5xx、超时、DNS、无效 JSON/版本 | 自动回退本仓库最新 Release 页面；故障注入通过。 |
| API 与页面同时失败 | 保留已知可用版本，按服务端重试时间及 5 分钟、30 分钟、2 小时、24 小时策略退避；后台不弹错误窗口。 |
| 页面发现版本 | 从可信标签构造两架构安装包和 SHA256SUMS.txt 直链。页面回退没有正文，说明窗口提供完整 Release 链接。 |
| 附件获取 | 页面回退的 size=0 会先请求附件 HEAD 确认大小；后续下载不依赖 API。附件失败不会替换当前应用。 |
| 完整性与准备 | 校验 DMG 大小、SHA-256、包标识、版本、架构与签名；只读挂载、临时复制后再次验签。 |
| 安装助手 | 隔离测试验证成功替换、等待旧进程退出、失败回滚与路径拒绝；实际系统启动仍需真机验收。 |

本轮修复：API 返回非法版本时继续页面回退；支持 Retry-After 的 HTTP 日期与数字秒数、503 退避，并遵守较晚截止时间；收紧 API 最终 URL、页面和附件来源检查。
