# 普通日志模式完成提示与未知状态修复

状态：修复已由用户本地验收并合入主分支，纳入 v0.1.31 / Build 34 发布。正式发布结果以 GitHub Release 为准。

## 问题与边界

当前代码可稳定复现：聚合摘要同时包含最近完成与未知记录时，菜单栏先显示完成对勾，30 秒后完成计数过期，再显示未知问号。刘海展示另有一套不同的优先级。现场未能还原当时 App 内存中的具体未知记录，不能将复现机制当成对该记录身份的确认。

本次只修改普通日志模式；Hooks 的覆盖、健康度和完成语义保持原样。未知证据不被转换为完成或“全部任务空闲”。

## 确认后的行为

- 确认执行中仍展示数量；完成反馈持续约 4 秒，最后一个任务结束后恢复中性图标。
- 中性仅表示当前未检测到执行中任务。
- 局部日志缺失、读取异常和过期未结束记录仅内部保留，不在主图标、菜单、详情或 tooltip 中单独提示。
- 整体监测故障同样不单独展示；没有已确认执行中任务时中性，不能推断完成。
- 30 分钟没有有效执行证据的记录退出实时执行数，仍保留未确认诊断；新执行证据可重新纳入。
- 初次扫描、重启、重复读取不回放历史完成提示。
- 所有展示端共用同一状态含义；未知数量、异常原因和最后成功检查时间只作内部诊断，不向用户呈现。

## 验收场景

1. 单任务开始、完成、4 秒反馈到期。
2. 完成与历史未知并存，图标回到中性、不展示诊断。
3. 多任务并行中一项完成，剩余执行数继续显示。
4. 完成后立即新任务，执行中优先。
5. 数据库不可读、全部候选文件读取失败时不展示问号或诊断，以及故障恢复。
6. 单条文件失败不掩盖其他已确认任务。
7. 重启、首次发现旧完成文件、重复事件不重播反馈。
8. 30 分钟过期、新执行证据恢复；无关事件不能续期。
9. 菜单栏、浮窗、Touch Bar、刘海呈现模型一致。
10. Hooks 回归保持原行为。

不启动桌面原生窗口、不替换安装包、不进行版本发布。

## 用户后续调整

用户明确要求局部未确认与整体监测故障均直接忽略，不单独呈现；此要求取代先前方案中的诊断行与整体故障问号。内部证据分类保留，Hooks 不变。

## 实施与验证结果

普通日志模式已接入 4 秒完成反馈，首次扫描建立基线；新增完成以匿名哈希身份去重，缓存保留 1 小时且最多 1024 项。有效执行事件更新运行证据，终态后的同轮或缺少轮次 ID 的统计事件不重新激活任务。局部未确认与整体故障只作内部分类，不再向用户展示问号或诊断。Hooks 语义不变。

验证通过：

- `bash scripts/test-task-status.sh`：74 项，含状态转换、去重、基线、有效事件、未知与故障中性展示、刘海完整数量及菜单不泄露诊断。
- `bash scripts/test-hook-integration.sh`：模式切换、默认开关与回调隔离通过。
- `bash scripts/test-hooks.sh`：41 项测试、7 个测试组通过。
- `swift build`：构建通过；仍有当前 Command Line Tools 环境的搜索路径警告。
- 文档本地资源引用及 `git diff --check` 通过。

日志位于本工作区 `.build/task-status-tests/`。没有运行桌面窗口或实体刘海/Touch Bar 验收，没有替换已安装应用；相关原生展示模型已做无窗口验证。更新后的完整原生窗口测试尚未执行。
